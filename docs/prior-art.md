# Prior art survey

This survey records adjacent systems without claiming that they are equivalent or deficient outside their stated scope. Dates identify public introduction or announcement and should be checked against the linked primary source before publication.

| System | Date and documented capability | Distinction from this specification |
|---|---|---|
| Android Intents | **2008 Android 1.0 release.** Android's application model included Intent messages for requesting actions from app components, with explicit and implicit resolution through intent filters. See Android Developers Blog, [Announcing the Android 1.0 SDK, release 1](https://android-developers.googleblog.com/2008/09/announcing-android-10-sdk-release-1.html), Sept. 23, 2008, and Android Developers, [Intents and intent filters](https://developer.android.com/guide/components/intents-filters). | Intents are component messages and resolution rules; this proposal adds a planner-facing typed tool catalog, effect metadata, scoped cross-app agent grants, and per-call brokering. |
| Android App Actions | **2018 announcement, not 2019.** Google announced App Actions at Google I/O 2018 as a way for Assistant to invoke app functionality. See Android Developers Blog, [What's new in Android P Beta](https://android-developers.googleblog.com/2018/05/whats-new-in-android-p-beta.html), May 8, 2018. | App Actions expose selected app functions to Google Assistant; this proposal defines planner-independent OS registration, delegated capability bundles, and multi-provider composition. |
| Android AppFunctions | **Experimental preview; Android 16+.** Android documents an OS registry of typed app functions, XML schema generation, discovery and execution by authorized callers, and multi-app orchestration. As of May 2026, Gemini integration was in private preview. See Android Developers, [Overview of AppFunctions](https://developer.android.com/ai/appfunctions). | AppFunctions covers much of the proposed registry. This specification adds a portable manifest and conformance model, user-inspectable tool and data-flow grants, audit semantics, and an explicit complexity router. |
| Apple App Intents | **2022.** Apple introduced the App Intents framework for exposing app actions and entities to system experiences including Shortcuts and Siri. See Apple Developer, [App Intents](https://developer.apple.com/documentation/appintents) and WWDC22 session [Dive into App Intents](https://developer.apple.com/videos/play/wwdc2022/10032/). | App Intents provide typed system integrations; this proposal separately registers procedural Skills and MCP operations, then authorizes cross-app plans through an explicit agent grant and device broker. |
| Rabbit large action model (LAM) | **2023.** Rabbit's 2023 funding announcement described LAM as modeling human actions on computer applications; the r1 product followed in 2024. See rabbit, [rabbit inc. raises $20M to build a natural language-powered personalized operating system](https://www.rabbit.tech/newsroom/rabbit-raises-20m) and [Introducing rabbit r1](https://www.rabbit.tech/newsroom/introducing-r1). | LAM is a model/product approach to action execution; this proposal defines an OS-governed schema, provider identity, grant, and audit contract rather than relying on interface imitation as the primary contract. |
| Anthropic Model Context Protocol (MCP) | **2024.** Anthropic introduced MCP as an open protocol for connecting AI assistants to systems that provide data and tools. See Anthropic, [Introducing the Model Context Protocol](https://www.anthropic.com/news/model-context-protocol), Nov. 25, 2024. | MCP defines client-server context and tool exchange; this proposal adds APK-time declaration, an OS-maintained mobile registry, Android identity binding, user-delegated cross-app scope, and device-side enforcement. |
| OpenAI Operator | **2025, not 2024.** OpenAI publicly introduced Operator as a research preview on Jan. 23, 2025; it used a browser and a computer-using model to interact with graphical interfaces. See OpenAI, [Introducing Operator](https://openai.com/index/introducing-operator/). | Operator is an agent product centered on browser UI interaction; this proposal is a mobile OS capability contract based on declared typed tools and local authorization. |

## Notes on scope

Android Intents and Apple App Intents are mature platform mechanisms and should not be reduced to simple deep links. Anthropic MCP already defines typed tool discovery and invocation at the protocol layer. Android AppFunctions now provides app-declared functions, OS indexing, authorized discovery and execution, and multi-app orchestration. The design claim here is therefore limited to the additional portable manifest, fine-grained cross-app delegation and data-flow controls, audit semantics, and policy-visible local/cloud routing described in [the architecture specification](ANDROID-AGENT-HARNESS.md).

The user-supplied chronology lists App Actions as 2019 and OpenAI Operator as 2024. Google's primary App Actions announcement is dated 2018, and OpenAI's public Operator announcement is dated 2025, so this survey uses those verified dates. Rabbit described LAM in a 2023 company announcement, before the 2024 r1 launch.
